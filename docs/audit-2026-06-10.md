# Аудит проекта CryptoBotWeb — 2026-06-10

Комплексный аудит шестью специализированными агентами: backend API, Worker/стратегии, биржевые интеграции, фронтенд, база данных, DevOps/инфраструктура. Все находки READ-ONLY, код не изменялся.

**Статус выполнения:** ничего из найденного ещё не исправлено (на момент записи отчёта).

---

## Сводка: общая картина

Архитектура в целом здоровая:
- Авторизация без IDOR — везде проверка `UserId == GetUserId()`.
- Все денежные расчёты в `decimal`, округление к шагу лота в клиентах бирж.
- Позиционные режимы (one-way/hedge) соответствуют CLAUDE.md на всех трёх биржах дословно.
- Торговый цикл устойчив: одна упавшая стратегия не роняет остальные (двойной try/catch), клиенты диспозятся, scope на стратегию.
- Различение transport-fail vs «order not found» (коммит 28aba53) реализовано образцово на всех биржах.
- SmaDca — самый защищённый хендлер (двойная проверка перед reset, adopt partial fills, restart-sync с биржей).
- Ротация фандинг-тикеров не трогает активные позиции, защищена атомарным `jsonb_set`.
- VITE-секретов в бандле нет; Zustand ничего чувствительного не персистит; ключи бирж не логируются.

Но: **3 критические** и ~10 высокоприоритетных проблем.

## 🔴 Критические

### C1. Дефолтные секреты в коде и git
- `backend/src/CryptoBotWeb.Api/appsettings.json:5-14` — рабочие `JWT_SECRET`, `ENCRYPTION_KEY`, `admin123` прямо в git.
- `Program.cs:18,38,73` (API) и `Worker/Program.cs:14` — fallback через `??` на эти же значения. Без env-переменных приложение **молча стартует** с публично известными ключами → можно подписывать произвольные JWT и расшифровывать API-ключи бирж из дампа БД.
- `docker-compose.yml:37-40` — те же дефолты через `${VAR:-default}`.
- `.env.prod.example:14-15` — закоммичен **реальный пароль `AdminPass_2026`** и email `admin@cryptopizza.pl`. Пароль слабый (слово+год).
- Нюанс: API и Worker имеют **разные** строки-дефолты ENCRYPTION_KEY (`change-me!` vs `change-in-production!!`) — при старте без env они не смогут расшифровать данные друг друга.

**Действия:** ротировать админ-пароль на VPS немедленно (он уже в git-истории); убрать все fallback'и — fail-fast (`throw`) при отсутствии env; заменить значения в `appsettings.json` и `.env.prod.example` на плейсхолдеры.

### C2. Proxy failover не замкнут в торговом цикле
- `ProxyHealthTracker.ReportFailure/ReportSuccess` вызываются **только** из `AccountsController.cs:249,254,259` (ручной «Test connection»).
- В Worker (`TradingHostedService.cs:122` → `ExchangeServiceFactory.CreateFutures` → `SelectProxy`, `ExchangeServiceFactory.cs:86-104`) реальные сбои прокси никуда не репортятся.
- `SelectProxy` опирается только на TCP-precheck (порт открыт ≠ прокси работает: handshake/auth не проверяются, `ProxyHealthTracker.TcpProbeAsync:52-67`). Мёртвый-но-слушающий прокси будет выбираться снова и снова.
- Заявленный в коммите 350fc46 auto-fallback в реальной торговле деградирует до «первый прокси с открытым TCP-портом».
- Также: `SelectProxy` приватный, выбранный прокси наружу не отдаётся — это корень проблемы; внутри `Parallel.ForEachAsync` блокирующий `.GetAwaiter().GetResult()` на precheck (`ExchangeServiceFactory.cs:96`) — риск thread starvation при 20 стратегиях и мёртвых прокси.

**Действия:** фабрика должна возвращать фактически выбранный proxyId; Worker оборачивает вызовы биржи и вызывает `ReportFailure`/`ReportSuccess`; сделать `SelectProxyAsync`.

### C3. Нет атомарности Trade + StateJson и optimistic concurrency
- В хендлерах (особенно `SmaDcaHandler` — строки 110,124,137,145,153,164,175...) несколько последовательных `SaveChangesAsync` в одном тике. При OOM/потере питания между ними — рассинхронизация State ↔ история сделок.
- `Strategy.cs` без `RowVersion`/`xmin`/`[ConcurrencyCheck]` — воркер (каждые 5с) и API (Start/Stop/ClosePosition/ResetLosses) могут перетирать `StateJson` друг друга. `SyncIfClosedExternally` прикрывает только сценарий внешнего закрытия.

**Действия:** явные транзакции для критических путей (Trade + StateJson); `UseXminAsConcurrencyToken()` на Strategy или `ExecuteUpdateAsync` в API.

## 🟠 Высокий приоритет

### Риск капитала
- **H1. Мартингейл EmaBounce без потолка** — `EmaBounceHandler.cs:265-309`, `EmaBounceConfig.cs`. `OrderSize × MartingaleCoeff^ConsecutiveLosses` растёт геометрически без лимита — нет `MaxOrderSize`/`MaxConsecutiveLosses`. Единственная стратегия с неограниченным ростом ставки. Главный денежный риск воркера. (У позиций есть TP/SL — проблема в накоплении ставки, не в одной сделке.)
- **H2. `GetOpenPositionsAsync`/`GetOpenOrdersAsync` глотают transport-fail** и возвращают пустой список, неотличимый от «реально пусто» — `BybitFuturesExchangeService.cs:534-572`, `BitgetFuturesExchangeService.cs:600-638`, `BingXFuturesExchangeService.cs:409-446` + все `GetOpenOrdersAsync`. Если на них завязан reconcile/orphan-cleanup в хендлерах — риск ложной чистки при сбое прокси. Выровнять с подходом `GetPositionAsync` (throw при сбое).

### Производительность / надёжность
- **H3. REST-клиент пересоздаётся на каждый тик каждой стратегии** — `TradingHostedService.cs:122`. До ~240 клиентов/мин при 20 ботах, каждый со своим HttpClient + AutoTimestamp server-time probe. Socket churn (TIME_WAIT), риск исчерпания ephemeral-портов, лишний rate-limit, пересоздание SOCKS5-туннелей. Кэшировать клиенты per-(account+proxy) с PooledConnectionLifetime.
- **H4. Нет Polly-retry и явных `RequestTimeout`** у клиентов бирж — на висящем прокси запрос блокирует тик на весь дефолтный таймаут SDK. Выставить 8-10с; retry с backoff на 429/5xx (ордера — только с client-order-id).
- **H5. Нет индекса на `strategies.Status`** (`AppDbContext.cs:98-120`) — seq scan каждые 5 секунд воркером. И **нет индекса на `trades.ExecutedAt`** — нужен составной `(StrategyId, ExecutedAt)` (`AppDbContext.cs:136-158`).
- **H6. `GetStats`/`GetTopBots`/`GetWorkspaceDetail` грузят все трейды** через `Include(s => s.Trades)` в память без `AsNoTracking` — `StrategiesController.cs:78-83,179-189`, `DashboardController.cs:70-71,94-98`. Заменить на SQL-агрегацию.
- **H7. `strategy_logs` и `trades` без retention** — безлимитный рост (~100-200k записей/мес при 5 активных ботах). Фоновая очистка / партиционирование.
- **H8. Race condition в `/start`** — `StrategiesController.cs:376-383`: два параллельных запроса обходят лимит активных ботов (check-then-act без блокировки).

### Безопасность веба
- **H9. CORS `AllowAnyOrigin()`** — `Program.cs:53-59`. Ограничить `WithOrigins("https://bot.cryptopizza.pl", ...)`.
- **H10. Нет rate limiting на `/api/auth/*`** — брутфорс паролей (минимум 6 символов). Добавить `AddRateLimiter`, минимум пароля 8-10.
- **H11. Refresh-токены не инвалидируются** — `AuthController.cs:56,66-85`: JWT 7 дней, не хранится в БД; после смены пароля/бана живут до 7 дней; нет logout-инвалидации. Таблица `refresh_tokens` с `IsRevoked`.
- **H12. nginx без security headers** — `frontend/nginx.conf`: нет HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy.
- **H13. Dockerfile'ы под root** — `Dockerfile.api:14-19`, `Dockerfile.worker:14-17`, `frontend/Dockerfile.prod:8-11`. Добавить non-root USER (для nginx менее критично).
- **H14. У API нет healthcheck** в docker-compose; frontend зависит от api простым `depends_on` без `condition: service_healthy`.
- **H15. Порт Postgres 5433 наружу** — `docker-compose.yml:18-19`. На VPS без firewall — открытая БД. Убрать ports в прод / dev-only override.
- **H16. AES-режим не зафиксирован** — `EncryptionService.cs:18,37`: `Aes.Create()` без явного Mode/Padding (платформенный дефолт CBC+PKCS7, без аутентификации). IV случайный — это хорошо. Лучше AES-GCM (`nonce|tag|ciphertext`); ключ деривируется голым SHA256 (`EncryptionService.cs:13`) — ок для энтропийных ключей, документировать.

### Фронтенд
- **H17. Race condition при параллельных 401** — `frontend/src/api/client.ts:17-51`: флаг `_retry` per-request, несколько одновременных 401 → несколько параллельных refresh → ложный logout. Нужен глобальный refresh-lock (общий promise).
- **H18. Polling логов каждые 3с по 500 записей** — `ActiveBotsPage.tsx:8024`; polling strategies каждые 5с — `:171`. Нигде нет `refetchIntervalInBackground: false`.

## ⚪ Низкий приоритет / заметки

- **Расхождение CLAUDE.md ↔ код:** SmartGridHedge НЕ вызывает `/v5/position/switch-mode` — только probe hedge-режима и останавливается если не включён (`SmartGridHedgeHandler.cs:105-150`). Поведение безопасное, но документацию надо поправить (или реализовать auto-switch).

- Нет `[MaxLength]`/`[Required]` на строковых полях DTO.
- `GetTopBots` `[AllowAnonymous]` раскрывает Id стратегий и торговые параметры (возможно, намеренно — лидерборд) (`StrategiesController.cs:170-265`).

- `ErrorBoundary` рендерит полный stack trace в production (`ErrorBoundary.tsx:60-68`).
- Роль читается из JWT без проверки подписи — подмена в localStorage показывает admin-UI (реальная защита на бэке, known limitation) (`authStore.ts:6-22`).

- Нет `npm audit` в пайплайне; `^`-версии в package.json.

- `payment_sessions.GuestToken` — полный индекс вместо частичного `WHERE NOT NULL`.
